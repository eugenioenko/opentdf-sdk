# Parity matrix

One row per exported symbol of the reference `platform/sdk` root package
([reference-api.json](reference-api.json), revision `4d9e555bddf0`)
and of the in-scope subpackages `auth`, `auth/oauth`, `experimental/tdf`,
`experimental/tdf/keysplit`, `httputil` and `sdkconnect`
([reference-subpackages.json](reference-subpackages.json)). The `audit` and
`codegen/runner` packages are excluded as build tooling and service-side
helpers ([full-sdk-plan.md](full-sdk-plan.md), "Not planned").

Columns: the reference symbol, its kind, the shared-source equivalent named
in [api-spec.md](api-spec.md), and the status: `done`, `phase N` (the phase
of [full-sdk-plan.md](full-sdk-plan.md) that delivers it) or
`not planned: <reason>`. Rows are grouped by the reference file that
declares the symbol. The table is generated by `scripts/parity-matrix.py`,
which encodes the phase assignments; edit the script, not the table.

A row turns `done` in the PR that delivers its symbol in the shared source (the
`DONE` set in the script). Phase 2 part 1 delivered the handle API, platform
discovery and the generated Go package; the symbols the plan lists under Phase 2
are all `done` in the shared source; part 2 exposes them through the generated
TypeScript and Python packages and part 3 through the Java, C#, Rust, C and Swift ones.
`ErrInvalid` moved to phase 4: it is declared in `granter.go`. Phase 3
delivered the service clients: `SDK.Call` in the shared source, typed accessors in
the Go, TypeScript and Python packages (part 1) and the Java, C#, Rust and Swift
packages, with one JSON function per method in C (part 2), so the `SDK` service
fields and every `sdkconnect` symbol are `done`. Part 3 delivered the attribute
helpers, `SDK.Auth`, `SDK.Conn` and the `WithCustom*Connection` endpoint overrides
on every target; with them `ErrAttributeNotFound`, `ErrAccessTokenInvalid` and
`ErrInvalid` (the FQN parsers of `granter.go`) are `done`. Phase 4 part 1 ported
`granter.go`, `key_splitter.go` and `resource_locator.go` and the autoconfigure writer:
the FQN types, `ResourceLocator`, the `KeySplitter` contract types and the
`WithAutoconfigure`/`WithDataAttributes`/`WithDataAttributeValues` options are `done`;
`DefaultKeySplitter` moves to phase 10 with the chunked writer that takes it.

Goalchemy issues opened for the gaps the phases depend on, detailed in
[goalchemy-gaps.md](goalchemy-gaps.md):
[#71](https://github.com/eugenioenko/goalchemy/issues/71) `std/net/url` (phase 2; released in v0.6.3 and pinned),
[#72](https://github.com/eugenioenko/goalchemy/issues/72) RFC 8785 JSON canonicalisation (phase 5),
[#73](https://github.com/eugenioenko/goalchemy/issues/73) `std/os` file handles, `CreateTemp` and `Rename` (phase 7),
[#74](https://github.com/eugenioenko/goalchemy/issues/74) `lib/runtime` host OS, architecture and version (phase 5),
[#75](https://github.com/eugenioenko/goalchemy/issues/75) bounded JSON Schema validator (phase 6),
[#76](https://github.com/eugenioenko/goalchemy/issues/76) X.509 certificate public key for `x5c` (phase 5).
